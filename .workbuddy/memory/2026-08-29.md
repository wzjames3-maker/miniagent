### 开发中发现并修复的真实 Bug（重要，都是踩过的坑）
1. **Windows 换行**：`Path.write_text` 会把 `\n` 转成 `\r\n`，导致已含 CRLF 的内容
   变成 `\r\r\n`。统一改为 `_write_text()` 字节写入。
2. **权限兜底规则覆盖具体规则**：`evaluate` 原为"最后匹配者胜"，默认规则集末尾的
   `*: ask` 会覆盖 `read: allow`。改为**最具体者优先**（特异性评分：通配符 0/部分 1/精确 2），
   平局才后者胜。
3. **`*` 不跨 `/`**：`rm -rf *` 匹配不到 `rm -rf /etc`。保持 glob 语义但补充
   `rm -rf **`，并让 `**/` 前缀匹配零个目录（ripgrep 行为，`**/*.env` 能匹配顶层 `.env`）。
4. **单轮长任务无法压缩**：compaction 只在 user turn 边界切分，长任务只有一个 user turn
   就永远不触发。改为：多轮按 user 切分，单轮退化到 assistant step 边界。
5. **配置 `type:` 字段被静默丢弃**：`ProviderSpec.from_config` 只认 `kind`，
   导致所有 provider 都回退 openai 协议，Anthropic 根本配不上。修为接受两者。
6. **provider 专有选项被丢弃**：`max_retries` / `min_request_interval` 等不在
   ProviderSpec 字段中就被过滤掉。改为转发到 `options`。
7. **非交互模式自动批准（安全缺陷）**：`non_interactive=True` 把权限模式切成 AUTO，
   导致 `minicode run` 默认批准一切。修为只有显式 `--yolo` 才 AUTO，其余 fail-closed。
8. **`provider/model` 拼错会静默建一个假 provider**：改为显式 provider 未知时抛 KeyError。

### 针对推理模型（deepseek-v4-flash）的处理
- 该模型把思考放 `reasoning_content`，`content` 常为空
- provider 提取 reasoning，UI 灰显展示，结束后折叠为一行统计
- Agent 层：空 content + 无 tool_calls 时 nudge 一次（仅一次）要求给出文本结论
- 该端点有 RPM 限制 → 加指数退避 + 遵守 `Retry-After` + `min_request_interval` 节流
