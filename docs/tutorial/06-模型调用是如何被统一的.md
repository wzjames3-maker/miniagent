# 06 模型调用是如何被统一的

**换厂商为何不改循环？**

> 定位：我们在全局图的 Model/Provider 格，看循环另一侧的翻译。

## 统一的语言

`src/minicode/providers/base.py` 定三种形状：`ToolCall(id,name,arguments,raw_arguments)`、`AssistantMessage(content,tool_calls,usage,reasoning)`、`StreamEvent(text/reasoning/tool_call_*)`。`tool_schema_to_openai/anthropic` 互译，`format_tool_results` 配对 `ToolResult` 为 `role: tool`。

`Provider` 抽象在 `base.py:221`，构造收 `model/api_key/base_url/max_tokens/options`，子类只实现 `generate(messages,tools,stream,on_event)`，其余为兼容 `mini-swe-agent` 的透传。`MiniModelAdapter` 因此可把 `Provider` 当 `Model` 用。

## 两类兼容层

`OpenAICompat`（`openai_compat.py:69`）覆盖 DeepSeek/Qwen/Ollama 等：`_convert_messages` 还原 `tool_calls`，`_run_stream` 逐 `chunk` 拼 `collected/reasoning/pending` 并 `on_event` 实时回放。用量在 `_usage:303` 兼容 `prompt_tokens_details.cached_tokens` 与 DeepSeek 的 `prompt_cache_hit_tokens`，统一入 `Usage.cache_read_tokens`；错误在 `_map_error` 识别 `context length` 文本为 `ContextLengthError`。

`AnthropicCompat` 同理，另上报 `cache_read/write`。重试与限流不在此，皆在基类。

## 重试与限流

`base.py:321` 的 `_throttle` 按 `min_request_interval` 睡眠，`_with_retries:344` 对 `RateLimit/ProviderAPI` 指数退避并取 `Retry-After` 较大值，`ContextLength/Authentication` 不重试（前者交 `Agent` 去压缩）。

`ProviderRegistry`（`registry.py:83`）解析 `type: openai_compat|anthropic_compat|litellm|my.mod:Cls`，`get("provider/model"|"model")` 三态查找，`options` 透传 `max_retries` 等不丢弃。
