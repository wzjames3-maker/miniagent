# 09 为什么需要权限来兜底

**如何不让 `rm -rf` 被执行？**

> 定位：我们在全局图的安全边界，看 `Agent` 调工具前的最后一道门。

`src/minicode/permission` 独立于 `tools/session/ui`，只答 `allow/deny/ask`。

规则为 `permission/pattern/action`，`pattern` 用 `*`（段内）、`**`（跨段）、`**/`（零级）、`?`（单字），实现在 `policy.py:147` 的 `wildcard_match`。配置支持 `read: allow` 与 `bash: {"git *": allow}` 双形态，`$HOME` 展位。

命中按 `_specificity:152` 最具体优先、平局后者胜，解 `*:ask` 覆盖 `read:allow`。

`PermissionManager:66` 分 `DEFAULT`（`deny→ask→allow`）与 `AUTO`（`--yolo` 下非 `deny` 即放行）；无交互时 `non_interactive` 直接 `PermissionRejected` 而非放行；`ALWAYS` 仅记精确 `pattern`。

`BashTool:34` 的 `destructive_targets` 双提取（`shlex` 主 + 正则兜底 `bash -c 'rm …'`）命中则追加 `delete` 二次校验，`default.yaml:27` 双拒 `rm -rf */**`。
