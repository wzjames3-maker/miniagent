# 08 对话太长时如何不崩

**长任务如何不撑爆窗口且不弄丢前缀缓存？**

> 定位：我们在全局图的记忆格，后半：太长时如何瘦身并保缓存。

## 三层

`src/minicode/context/manager.py:1` 的 docstring 即缓存纪律：两次压缩间历史字节级稳定，剪枝只在压缩时发生，否则打断 OpenAI/DeepSeek 自动前缀缓存。

1. **截断** `truncate_tool_output:113` → `tools/truncate.py:48` 的 `2000 行/51200 字节` 超限写盘回 `output_path`，由 `ToolEnvironment` 经 `ctx.truncate` 统一注入。
2. **剪枝** `prune_tool_outputs:131` 倒序跳过 `prune_protect_tokens(40k)` 与末轮 `assistant`，达 `prune_minimum_tokens(20k)` 才擦为 `[tool output removed…]`。仅由 `compact:224` 与 `rebuild:323` 调用，永不在 `prepare` 间单独执行。
3. **压缩** `compact:224` 以 `_select_split:196`（多轮按 `user`、单轮按 `assistant`）和 `preserve_recent_tokens:20000` 予算选切点，`head` 经 `COMPACTION_TEMPLATE` 调模型或 `fallback_summary`，包为 `role: user` 的 `<compaction>` 插于 `system` 后。

## 何时触发

`prepare:309` 达 `0.85*max_tokens` 则 `compact`（首阶段即剪枝），否则 `pruned_tokens=0, after=before` 直接返回，不碰历史。`rebuild:323` 仅剪枝。估算在 `tokens.py:29` 偏保守（`CJK 1.3 / ASCII 3.6`），仍以 `ContextLengthError` 的 `_force_compact` 兜底。

## 记住什么

截断每次、压缩达阈（内含剪枝）、平时不碰历史。下一章看边界。
