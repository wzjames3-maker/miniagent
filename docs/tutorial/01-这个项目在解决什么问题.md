# 01 这个项目在解决什么问题

**为什么要做 minicode，而不是直接调一次模型 API？**

## 一个任务需要反复动手

你让模型“修好 `parse_date` 对空字符串的崩溃”。单次 `client.chat.completions.create` 只能返回一段猜测的代码，看不到文件、跑不了测试。

你需要的是能反复动手的循环：先看文件 → 再改 → 再跑 `pytest` → 看结果再决定。模型提需求，程序去执行，结果再回到模型。这个循环就是全部。

## 三者的位置

`README.md` 第一句点明：用纯 Python 复刻 OpenCode 的核心思路，以 `mini-swe-agent` 的循环为底座。

- `mini-swe-agent` 已有循环与 `bash` 执行
- OpenCode 证明“多工具、多权限、多会话、上下文管理”合在一起才可在大仓库干活，但为 TypeScript/Bun
- minicode 取后者设计、前者循环，用 Python 重做一个小而完整的版本，依赖仅 `mini-swe-agent`/`openai`/`anthropic`/`textual`（可选）

## 一个叶子模块的价值

`src/minicode/project.py` 不依赖项目内任何代码，注释强调“叶子”。

它做两件事。先看根目录的 `pyproject.toml`/`package.json`/`go.mod` 等，推断语言与 `pytest`/`npm test`/`go test` 等命令；再读 `AGENTS.md`/`CLAUDE.md`（`INSTRUCTION_FILES_LOADED`，单文件 20k 截断，`instruction_block`），拼进系统提示词。前者让模型在不同仓库用对命令，后者让仓库的协作约定自动生效。

同一份判断喂给三处：提示词的 `{{ project }}` 与 `{{ project_instructions }}`、权限的放行列表、配置的生成，避免“建议 `npm test` 却被权限拦”的分叉。

## 记住什么

它要解决的不是“如何调模型”，是“如何让模型持续、带权限、带记忆地在真实仓库完成任务”。
