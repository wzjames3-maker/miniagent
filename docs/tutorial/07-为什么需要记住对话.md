# 07 为什么需要记住对话

**一轮后如何知道之前发生了什么？**

> 定位：我们在全局图的记忆格，前半：如何记住。

## 没有记忆会怎样

无记忆则每轮只能见当前一句，`read` 过的文件与 `edit` 的 `diff` 皆丢，模型只能猜。

## 存什么

`src/minicode/session/models.py:59` 的 `Session` 为纯数据：`id/title/provider:str/model:str/cwd/messages/tool_calls`。`ToolCallRecord` 记 `duration_ms/output_chars/truncated/error_code`。纯数据才能跨进程 `create/resume/fork`，不拖活的 `Provider`。

## 怎么存

`src/minicode/storage/json_store.py:18` 的 `atomic_write_json` 以 `mkstemp→write→fsync→os.replace` 原子落盘，`Lock` 防并发；单根在 `storage/paths.py:26`（`MINICODE_DATA_DIR` 可覆写），含 `sessions/truncation`。`SKIP_DIR_NAMES:60` 同时被 `grep` 与 `glob` 共享，保证两条搜索路径行为一致。

`SessionManager:29` 的 `create(persist=False)` 让空会话不立即落盘免 `New session` 占位；`_switch_session` 经 `ContextManager.rebuild` 剪枝后重建 `Agent`；`fork:155` 按 `messages[:cut]` 的 `tool_calls` 数同步截断。

`InteractiveApp:223` 的 `known_sessions(cwd=...)` 按 `_same_cwd` 过滤并插入未落盘的 live 会话，供 TUI 左栏。

## 记住什么

记忆靠纯数据与原子落盘。下一章看太长时如何瘦身而不打断缓存。
