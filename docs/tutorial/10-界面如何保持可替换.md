# 10 界面如何保持可替换

**换界面为何不改循环？**

> 定位：我们在全局图的界面格。

两契约：`EventSink:19`（`Agent→UI` 的 `on_stream_event/on_tool_start/on_tool_result/on_compaction`）与 `UIPort:43`（`App→UI` 的 `banner/status_line/ask_permission`），合为 `UIFrontEnd`（`port.py:44` 的 `runtime_checkable Protocol` 组合，半实现在首个事件即暴露）。`InteractiveApp:33` 用同一对象兼任，核心只认契约。

`ConsoleUI:42` 主线程直出 `Rich` 的 `Panel` 与 `Prompt.ask` 阻塞；`TextualUI:32` 经 `MiniTUI.post:157` 的单点线程判断（`call_from_thread` 禁在 UI 线程调）回投，`_PendingPrompt` 以 `Event` 挂起工作线程、`on_permission_bar_answered:222` 与 `on_composer_submitted:233` 统一收尾，避免残留弹窗。`ui/render.py` 的 `clip_lines/format_arguments` 为两前端共享。

状态栏经 `port.py:44` 的 `cache_label/fmt_tokens` 渲染 `cache 12.3Kr/4.5Kw`（`widgets.py:153` 的 `ContextBar` 同款，`in/out + cache + ctx bar` 一行可见），`format_status_line` 保证两端不分叉。

`cli/commands.py:32` 的斜杠分发仅依赖 `UIPort`，故同表在两前端一致，`_switch_session` 经 `ContextManager.rebuild` 重建 `Agent` 也经此契约。

## 记住什么

核心不认具体界面，新增前端只需实现两契约；线程判断只允许在 `MiniTUI.post` 一处。
